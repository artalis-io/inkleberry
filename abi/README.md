# Native CUDA ABI schema

`cuda.json` is the authoritative declaration schema for the C host's native CUDA
boundary. It is separate from the public serving ABI in `include/ifn_infer.h`.
The initial schema contains the existing 76 functions, seven records and 72
layout checks. It was bootstrapped from the already-qualified C declarations;
no Zig source or compiler is used by the generator.

The schema and generated artifacts retain Apache-2.0 attribution. Initial
signatures/layouts derive from the pinned tensorfish implementation recorded in
`UPSTREAM.json`; the actual unchanged CUDA C++ bridge is the independent compiler
oracle. The generator does not read that manifest or the reference tree.

## Type grammar

- Scalars: `uint8`, `uint32`, `uint64`, `int32`, `float32`, `usize`, `void`.
  `usize` maps to the platform's native `size_t`; this is not a wire format.
- Previously declared record names may be used as field types. Records are
  ordered; forward/cyclic definitions are outside schema v1.
- `pointer<T>`: mutable pointer to T.
- `pointer<const,T>`: pointer to const T. Qualifiers bind at that level, so
  `pointer<const,pointer<float32>>` becomes `float * const *`.
- A record field's optional integer `count` specifies a fixed array, such as
  the three DSpark layers. Arrays in function parameters are not implicit pointers.
- A record's optional `cpp_type` names its actual CUDA C++ type, for example
  `squid::SampleConfig`. Otherwise the bridge uses the record's existing name.

Schema version 1 rejects unknown keys, duplicate symbols/fields/parameters, C/C++
keywords or invalid identifiers, unknown types, invalid array counts, excessive
pointer nesting, duplicate JSON keys and non-JSON numeric constants. Files are
bounded to 1 MiB. Validation finishes before any output is written. Metadata is
not executable code; arbitrary C declarations/includes are not accepted.

## Generation and verification

```sh
python3 tools/generate_cuda_abi.py
make generated-check              # production pins, generated bytes, schema tests
make cuda-abi-check               # actual CUDA C++ signatures and layouts
make cuda-abi-negative-check      # intentional signature/layout mismatches rejected
make reference-free-check        # C check/install-check with every Zig file absent
make reference-check             # optional: also verify all pinned Zig reference bytes
```

Generated artifacts:

- `src/cuda_abi.h`: C declarations.
- `test/cuda_abi_c.c`: C `sizeof`, alignment and offset table.
- `test/cuda_abi_probe.cu`: includes the actual CUDA C++ bridge, checks function
  declarations at compile time and compares its own native record layouts with C.

The C++ probe never synthesizes replacement CUDA record definitions from the
schema. Both sides being generated does not make the layout check self-confirming:
expected sizes/offsets come from actual CUDA types, and function definitions come
from the unchanged real bridge. Negative tests independently demonstrate rejection
of a wrong return type and a wrong C record size/offset layout.

`--schema PATH` and `--output-root DIR` support isolated generation/testing.
`--check` is read-only and fails on stale or missing artifacts. The generator's
only input is the schema; Python standard library is sufficient. It describes the
native declaration/layout contract, not pointer ownership, nullability, lengths
or host/device lifetimes; those remain the implementation/API contracts.

`test/fixtures/cuda_abi_v1.json` is a compatibility hash anchor for the initial
artifact payloads, excluding only their leading attribution comment. It is not a
second ABI definition. An intentional contract change requires explicit review of
that anchor, schema, bridge compatibility and qualification; do not update expected
hashes simply to silence a regression. Format changes also require reviewing the
anchor, since it deliberately freezes these exact initial declarations/probes.

## Reference boundary

Normal production checks still verify the pinned license and CUDA files. They
skip only original names ending in `.zig`. Removing optional reference files must
not weaken kernel verification. Oracle targets depend on `reference-check`, which
also verifies every pinned Zig file before compiling the optional comparisons.
The original reference remains available; it no longer defines the C build's ABI.
