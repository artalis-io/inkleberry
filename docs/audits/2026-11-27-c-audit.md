## Analyzer triage

Clang 22.1.8 (`arm64-apple-darwin25.6.0`) static analysis executed on all 29 canonical C translation units: nine
warnings, no compiler failures. Eight warnings are unconfirmed/triaged false paths:

- `engine_runtime.c:60`: the trace returns `ifn_error(IFN_BUSY, ...)` before scope
  initialization, then assumes the caller saw IFN_OK. `ifn_error` returns its
  supplied status, so that branch is contradictory.
- `safetensors.c:221` and `:252`: analogous allocation-failure paths assume
  `ifn_error(IFN_OUT_OF_MEMORY, ...)` becomes success. Constructors clear output
  and callers return on nonzero status; allocation-fault tests cover these paths.
- `safetensors.c:305` and the two `:321` diagnostics: the traces take a not-found
  index path in `ifn_safetensors_at`, then assume its nonzero status is success.
  The caller returns before dereferencing/subtracting the cleared pointer.
- `tokenizer.c:458`: the trace combines `out == NULL, capacity == 0` with passing
  the nonempty fixed prompt-prefix capacity check. Checked size additions cannot
  produce that successful zero-size path.
- `weights_runtime.c:135`: the trace observes a nonzero weight construction status
  and then assumes the returned status is zero. Manual result-path review and
  allocation/recipe fault tests do not reproduce a null dereference.

Host amalgamation analysis leaves the weights warning; CUDA-enabled C-host
amalgamation leaves that warning and A3. No source annotations or suppressions
were added to silence these candidates. Analysis did not compile/analyze CUDA
SDK device bodies. It is not recorded as a warning-free analyzer pass.
